What the gate does, state by state

The requirement is… …and designing scenarios does this
Not captured at all Passes straight through. Every spec-first workflow that existed before behaves exactly as it did.
Draft or rejected Held back, and an amber banner names the endpoints that were dropped.
Approved Planned, with its purpose, rules and expected responses folded into the brief the generator reads.
Unreadable — the lookup failed Falls through rather than blocking. A broken gate must not stop a team from working.

Verified live with real model calls: two endpoints selected, one approved. Thirteen scenarios came back, every one of them for the approved endpoint, none mentioning the held-back one — and the approved requirement’s business rules showed up in the scenario titles, proving the brief reached the planner.

That partial case was the one worth paying for. The fully-blocked path returns before any model call, so it was cheap to check; the partial path is where a bug would actually drop work silently — and it did, until it was found.
