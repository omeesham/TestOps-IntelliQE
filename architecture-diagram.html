🔄 Key Data Flows
🧪 Test Generation Flow
  • 1. Select test type (UI/API/Data/E2E)
  • 2. Import requirements (JIRA / manual)
  • 3. Configure target app + credentials
  • 4. AI Pipeline generates test cases
  • 5. Review, edit, save to DB
  • 6. Export as test suite
📊 Validation Drill-Down Flow
  • 1. Configure data source (Azure Blob)
  • 2. Create validation rules (17 operators)
  • 3. Execute → batch insert ~1,666 results
  • 4. Overview → Monthly summary
  • 5. Month → Daily breakdown
  • 6. Day → SCADA file table
  • 7. File → Individual test cards
💬 Chat / AI Flow
  • 1. Create conversation (per tenant)
  • 2. Send messages (user/assistant)
  • 3. Metadata stored as JSONB
  • 4. Credential sanitization on save
  • 5. TTS voice readback (optional)
🛡️ Security Architecture

🔒 Encryption in Transit

Frontend encrypts sensitive fields with XOR + Base64 before sending. Prefixed with __ENC__. Shared key between client & server.

XOR Cipher

🗄️ Encryption at Rest

Backend re-encrypts config_data JSONB before storing in PostgreSQL. Sensitive keys (25+ patterns) automatically detected and encrypted.

JSONB Encrypted

🎭 API Response Masking

All sensitive fields replaced with ••••• in API responses. Raw credentials never exposed to frontend.

Field Masking

💬 Chat Sanitization

Regex patterns redact SAS tokens, Bearer tokens, GitHub PATs, AWS keys from chat messages before saving to database.

Auto-Redaction

🏢 Tenant Isolation

Every query scoped by tenant_id. Auth middleware injects tenant context. Platform admin flag for cross-tenant access.

Row-Level Security

👁️ Role-Based Visibility

SQL expressions hidden from non-admin users. Sidebar items filtered by role. Admin-only pages enforced via routing.
